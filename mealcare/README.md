# 养老机构膳食过敏与送餐核对平台

管理住户饮食档案、过敏项、菜单营养审核、厨房批次、餐盒标签、送餐路线、
拒餐与替换记录的一体化本地系统。**纯 Python 标准库实现**(含自研二维码编码器),
无需安装任何第三方依赖;住户姓名与健康信息均为匿名演示数据。

## 一条命令启动

```bash
cd mealcare
./run.sh                 # 默认 http://127.0.0.1:8000
PORT=8080 ./run.sh       # 自定义端口
```

启动时会自动重建数据库并生成完整样例:**已审核菜单 → 厨房批次配餐 → 路线交接
→ 正常送达 / 温度不合格隔离与替换 / 错餐隔离 / 拒餐 / 漏餐 / 家属临时调整 /
送达追加说明 / 待双人确认的档案修改**。

> 也可:`python3 -m app`(数据库不存在时自动播种);加 `--no-seed` 使用现有库。

## 六个业务页面(顶栏可切换四种身份)

| 页面 | 内容 |
|------|------|
| 住户饮食卡 | 过敏/忌口/咀嚼要求**固定在卡片顶部**,过敏按等级高对比展示,含住户身份二维码 |
| 菜单审核 | 菜品与菜单两级营养审核;未过审菜品不能进菜单、不能做替换餐 |
| 厨房批次 | 大字 + 图标的餐盒标签;过敏项红色警示条;换菜即换签、旧签即时作废 |
| 送餐路线 | 一屏完成核对:固定高对比过敏横幅 + 两步扫码指示 + 单输入框 |
| 异常餐盒 | 错餐/漏餐/拒餐/温度/家属调整五类事件,隔离与处置闭环 |
| 家属确认 | 匿名家属来电调整:先登记、员工确认后执行、单独留痕 |

顶栏可切换 **护理主管 / 营养师 / 厨房 / 送餐员**,体验字段级权限差异
(例如送餐员看不到也无法执行审核、交接、家属确认操作)。

## 核心业务规则

- **过敏拦截**:配餐按菜单顺序自动绕开含住户过敏原、不满足咀嚼等级、
  命中忌口的菜品;替换餐二次复核;速发(可致命)等级在送餐端固定横幅提示。
- **营养审核状态机**:菜品 `draft→approved/rejected`;菜单
  `draft→pending_review→published/rejected`;发布前再次校验全部菜品仍有效。
- **餐盒标签**:标签号全局唯一(DB UNIQUE + 重试生成);替换餐**只能选已审核
  且不过敏菜品**;旧标签立即 `void`,扫到旧签一律拒绝。
- **送餐核对**:必须**先扫住户码、再扫餐盒新标签**双码齐全才完成交付;
  人盒不符/非本路线餐盒立即隔离;重复扫描返回 `duplicate` 并记拒绝事件,
  不产生第二条送达记录;路线未交接不能开扫。
- **异常隔离**:温度低于 60℃、错餐立即把餐盒置为 `quarantined`;
  隔离事实即使调用方回滚也会落库(发生即确定)。
- **双人确认**:档案修改由一名员工发起、**另一名不同员工**确认后才生效,
  申请人不可自确认;档案带版本号。
- **记录不可变**:已送达主记录(时间戳/送餐员/结果)无任何修改入口,
  只能通过追加说明补充。
- **进程内提醒**:后台守护线程轮询 `reminders` 表,到期推送至页面铃铛。

## 本地二维码适配器

`app/qr.py` 是零依赖的 QR Code(Model 2)编码器:字节模式、纠错等级 M、
版本 1–10 自动选择、Reed-Solomon GF(256)纠错、8 种掩码按规范罚分择优、
输出 SVG。已与 Nayuki 参考实现做 **v1–v10 全版本逐位矩阵比对(0 差异)**,
并用 jsQR 对真实渲染图做端到端解码验证(含中文与边界容量)。

真实扫码枪以键盘楔入方式把内容输入核对框;没有硬件时,**点击页面上的二维码**
即模拟一次本地扫描,两条路径共用同一套 `services.scan()` 核对逻辑。

## 测试

```bash
python3 -m unittest discover -s tests
```

57 个用例覆盖需求点名的五个重点:

- **过敏拦截**:过敏原/咀嚼/忌口三类拦截、配餐端到端零过敏、替换餐复核
- **餐盒标签唯一**:全局唯一、UNIQUE 约束、替换换签、旧签作废
- **路线交接**:交接前置、交接权限、先住户后餐盒、人盒不符隔离、非本路线拒绝
- **重复扫描**:交付后住户/餐盒重扫、路线完成后拒扫、拒绝事件留痕
- **字段权限**:角色-动作矩阵、营养字段/审核动作隔离、双人确认、
  送达记录只追加,以及温度阈值与家属确认权限

## 技术栈与数据

- Python 3.11 标准库:`http.server` + `sqlite3` + 自研 QR(无 Flask/pip)
- SQLite:`data/mealcare.db`(表结构见 `app/db.py`,含 `audit_log` 全量审计)
- 前端:原生 HTML/CSS/JS,暖白 `#fffaf3` / 橙红 `#e2574c` / 青绿 `#1f8f82`

```
mealcare/
├── run.sh                 # 单条启动命令
├── app/
│   ├── qr.py              # 二维码本地适配器
│   ├── db.py              # SQLite schema
│   ├── services.py        # 领域规则(拦截/审核/标签/扫描/权限)
│   ├── reminders.py       # 进程内送餐提醒
│   ├── seed.py            # 匿名演示样例
│   ├── web.py             # HTTP 服务与页面
│   └── static/            # style.css / app.js
└── tests/                 # 57 个 unittest 用例
```
